3. **Echo 다중 동시성 부하 검증** — 매치당 최소 40개 Echo 동시 존재 시 서버 CPU·대역폭이 설계 기준 범위 내일 것

## 검토 범위 및 방법론

- 근거는 공개 자료, 유사 타이틀 실적, 엔진 문서를 기반으로 한다
- 모든 기간 추정은 **최소 30% 버퍼를 포함**하며, 버퍼 포함 사실을 명시한다
- 낙관 추정을 제시하지 않는다
- 구현 코드·클래스 설계·엔진 API 지침은 범위 밖이다
- 판정이 불가능한 항목은 "판정 불가 + 필요한 추가 정보"로 표기한다

### 입력 문서와의 불일치

| 항목 | 검토 범위(이슈) | 제안서 실제 | 검토 기준 |
|---|---|---|---|
| 플레이어 수 | 최대 100인 배틀로열 | **60인** (3인 스쿼드 20팀) | 제안서 기준 60인으로 검토 |
| Echo 엔티티 | 별도 언급 | 사망자 전원이 Echo 전환 | 최악 기준 57 Echo 동시 존재 |

> ⚠️ **주의:** 제안서는 60인을 전제한다. 만약 향후 100인으로 확장할 경우 본 검토는 무효화되며, 아래 판정 다수가 RED로 변경된다. 100인 규모는 네트워크·렌더링·콘솔 세 축 모두에서 본 제안서의 인력·기간 범위 밖이다.

## 검토 1축: 기술

### 1.1 Echo 시스템 — 서버 권한 모델

**판정: YELLOW**

| 항목 | 분석 |
|---|---|
| **선례 유무** | 장르 내 직접 선례 없음. Apex 배너 부활, Warzone Gulag, Fortnite 리부트는 모두 사후 "전투 재진입" 모델. Echo는 **비전투 상태에서 월드 조작을 통한 간접 개입**으로, 개념적 신규성 높음 |
| **기술 구성요소** | (a) 사망 시 Echo 상태 전환 및 상태 머신 (b) Haunt 구역 설정 서버 권한 (c) Possess 오브젝트 조작 권한 이전 (d) Whisper 팀 채널 제한 (e) Soulflare 전역 이벤트 (f) Reclaim 부활 상태 복원 |
| **난이도 근거** | 개별 구성요소는 표준적 — Haunt는 서버 트리거 볼륨, Possess는 액터 소유권 이전, Whisper는 제한된 팀 VoIP/텍스트, Soulflare는 서버 측 적 위치 수집 후 필터링된 브로드캐스트. **난점은 이들을 하나의 일관된 Echo 경제 시스템으로 통합하고, 40+ Echo가 동시에 이들 기능을 사용할 때 서버 성능을 유지하는 것** |
| **Reclaim 데이터 정합성** | Reclaim(부활)은 "3킬 분량의 Echo 에너지 축적 → 스스로 부활, 매치당 1회, 팀당 1명"을 요구한다. 서버는 Echo 에너지 정수값을 권한 있게 추적하고, 부활 시 플레이어 캐릭터 재생성·인벤토리 복원·팀 상태 갱신을 원자적으로 처리해야 한다. 복잡하지만 표준 서버-권한 상태 머신 범위 내 |

#### Echo 다중 동시성 부하 분석

최악 시나리오: 60인 매치, 3명 생존, 57명 Echo 상태.

| Echo 능력 | 서버 부하 특성 | 동시 40+ Echo 시 영향 |
|---|---|---|
| Haunt | 구역 진입 감지 Polling → 트리거 볼륨 1개당 Tick 비용 낮음 | Echo당 1개 Haunt = 최대 57개 동시 볼륨. 적(생존자)이 이동 시 충돌 검사 O(n*m). 57개 볼륨 × 3명 생존자 = 171회/틱 충돌 검사. **수용 가능 (UE5 기본 충돌 최적화 범위 내)** |
| Possess | 오브젝트 소유권 이전 + 입력 전달. 서버가 오브젝트 상태 동기화 | 맵 내 Possess 가능 오브젝트 수에 종속. 제안서에 명시되지 않았으나, 설계가 문·함정·횃불 등 한정된 오브젝트 풀이라면 가벼움. 모든 오브젝트가 Possess 대상이면 서버 객체 풀링 필요 |
| Whisper | 팀 전용 메시지 라우팅 (서버가 중계만 함) | 부하 매우 낮음. 단순 텍스트/음성 중계 |
| Soulflare | 서버가 모든 적 위치 수집 → 아군에게만 브로드캐스트 | 전역 연산. 60명 중 아군(2명)에게만 브로드캐스트. 연산 부하는 낮으나 대역폭 스파이크 가능성 있음 |
| Echo 간 Dispel | Echo 간 상호작용. 서버가 Dispel 판정 → 에너지 이전 | Echo 수에 비례한 충돌/범위 검사. Echo 간 상호작용은 O(n²/2) 가능성. 57 Echo → 약 1,596쌍의 상호작용 검사 필요할 수 있음 |

**핵심 부하:** Echo-Echo 상호작용(Dispel)의 조합 폭발과 Soulflare 전역 브로드캐스트 대역폭. 적절한 거리 제한·빈도 제한으로 제어 가능하나, 프로토타입 검증이 필수다.

### 1.2 네트워크 아키텍처

**판정: GREEN (60인 기준) → 100인 확장 시 YELLOW**

| 항목 | 분석 |
|---|---|
| **서버 틱레이트 목표** | BR 장르 표준은 20-30 Hz 서버 틱 (PUBG 30Hz 목표, Apex 20Hz, Fortnite 30Hz). ECLIPSE: REQUIEM의 60인 규모는 30Hz 서버 틱이 표준적이며 달성 가능 |
| **이중 우선순위 네트워킹** | 생존자(액티브 전투)는 30Hz 풀 리플리케이션, Echo(비전투)는 10-15Hz 저빈도 리플리케이션으로 네트워크 우선순위를 분리하면 대역폭 절감 가능. UE5 Replication Graph로 엔티티별 우선순위 설정이 정식 지원됨 |
| **매치당 동시 접속자** | 60인 + AI 20-40체 = 80-100 네트워크 엔티티. 서버-클라이언트 모델 기준, 각 플레이어는 60명의 복제 액터 + 관련성 있는 AI만 수신. UE5 Replication Graph + Relevance 기반 필터링으로 표준 처리 가능 |
| **Dedicated Server 요구** | AWS GameLift 또는 자체 베어메탈. BR 60인 매치 기준 서버 사양: 4-8 vCPU, 16-32 GB RAM 인스턴스. AWS GameLift c5.4xlarge~c5.9xlarge 급 예상 |
| **비교 선례** | PUBG는 동일 규모(100인)를 커스텀 언리얼 엔진으로 처리. Apex는 60인을 Source 엔진 기반으로 20Hz에 처리. 둘 다 표준 Dedicated Server 아키텍처 |

### 1.3 AI 생태계

**판정: GREEN**

| 항목 | 분석 |
|---|---|
| **선례** | Hunt: Showdown — PvPvE, AI 몹이 전투 소음에 반응하는 Faction Aggro 모델 선례. ARC Raiders — 대규모 AI 개체 + PvP 혼재. Remnant II — 보스급 AI + 협동 |
| **AI 개체 풀링** | 20-40 AI 개체는 UE5 Behavior Tree + EQS로 충분히 처리 가능. 개체 풀링은 UE5 기본 World Partition 또는 커스텀 오브젝트 풀로 관리 |
| **Faction Aggro** | "소음 수준에 따라 몹이 몰려온다" → 서버 권한 AI 인식 시스템 (Sense Component). UE5 AIPerceptionComponent로 구현 가능하며 선례 다수 |
| **보스급 AI (Lord's Vassal)** | 단일 보스, 복잡한 페이즈별 행동 트리. UE5 Behavior Tree + State Tree로 표준 구현 가능. 문제는 보스 전투 중 주변 PvP 개입 시 서버가 PvPvE 3자 관계를 처리하는 것 — 난이도 추가 |
| **동적 몹 수 조정** | "동접 인원에 따라 동적 조정" → 서버가 플레이어 수를 모니터링하고 AI 스포너 풀을 조정. 간단한 스케일링 로직으로 구현 가능하나, 플레이어 경험 일관성에 영향 |

### 1.4 렌더링 및 성능 (UE5)

**판정: YELLOW**

| 항목 | 분석 |
|---|---|
| **Lumen + 고딕 환경** | 고딕 건축(석재·스테인드글라스·지하 납골당)은 Lumen GI가 탁월한 결과를 내는 표면 유형. 다크 판타지 톤은 전반적으로 어두운 씬 → 실내/야간 장면은 GI 연산 부하가 낮음. **환경 렌더링은 적합도 높음** |
| **영혼체 캐릭터 렌더링** | 반투명·발광 텍스처 → 전통적 PBR 셰이딩 비용보다 낮거나 비슷. 단, 다수의 반투명 캐릭터 오버드로(Overdraw)가 GPU 필레이트 바운드 유발 가능. 별도 Render Queue 또는 Forward Shading 경로 고려 |
| **Niagara VFX** | Echo 이펙트·영혼 파티클·Requiem 파도 시각화. UE5 Niagara는 GPU 파티클을 지원하며, 최적화된 상태에서 수백 개 이미터 동시 처리 가능. 다만 60인 전투 상황에서 모든 캐릭터·VFX·AI·환경이 동시에 표시될 때 GPU 바운드 불가피 |
| **Nanite 한계** | 고딕 건축물(석재·구조물)은 Nanite 최적 대상. 그러나 식생·반투명 오브젝트(스테인드글라스, 유령 이펙트 등)·얇은 구조물은 Nanite 미지원 또는 효율 저하. 묘지 구역(Sorrowfield) 식생 처리가 과제 |
| **60인 + AI + VFX 동시 렌더링** | 최악 시나리오: 최종 존에 5팀(15명)+AI 개체+광역 VFX+Echo 이펙트. UE5에서 60인 캐릭터는 스켈레탈 메시 업데이트 비용이 GPU·CPU 양측에 부담. 캐릭터 수에 따른 Draw Call·애니메이션 업데이트 병목이 주요 과제 |

### 1.5 콘솔 최적화 (PS5 / Xbox Series X|S)

**판정: YELLOW (Series S 때문에)**

| 항목 | 분석 |
|---|---|
| **PS5 / Xbox Series X** | 16 GB 통합 메모리, RDNA 2 GPU (~10-12 TFLOPS). UE5는 이들 플랫폼을 1차 타겟으로 지원. 60인 BR을 60 FPS 동적 해상도로 구동하는 것은 도전적이지만 달성 가능 — Fortnite는 이미 UE5로 PS5/Series X에서 120 FPS 모드 제공 |
| **Xbox Series S** | **본 프로젝트의 최대 단일 기술 리스크.** 10 GB 통합 메모리(게임 가용 ~8 GB), ~4 TFLOPS GPU. UE5 Lumen은 Series S에서 소프트웨어 레이 트레이싱으로 제한됨. 60인 캐릭터+AI의 메모리 점유와 GPU 부하는 Series S에서 극도로 타이트함 |
| **Series S 강제 제약** | Microsoft는 Series X와 Series S 간 게임플레이 패리티를 요구 (동일한 게임 모드·플레이어 수). 해상도·프레임레이트·그래픽 품질만 차등 가능. 즉, Series S에서도 60인이 동일하게 플레이 가능해야 함. 메모리 부족으로 텍스처 스트리밍 거리·AI 수·VFX 품질을 대폭 축소해야 할 가능성 |
| **플랫폼 인증 (TRC/TCR)** | PS5 TRC, Xbox TCR 준수 필요. 음성 채팅·크로스플레이(있다면)·세이브 데이터·네트워크 연결 안정성 요건. 첫 인증은 통상 2-4주, 실패 시 재제출 사이클 추가 |

## 검토 5축: 리스크

### 5.1 리스크 평가 방식

- **발생 확률 (P)**: 0.0-1.0
- **영향도 (I)**: 1-10 (10이 최대 영향)
- **조기 감지 가능성 (D)**: 0.0-1.0 (1.0이 가장 빠르게 감지 가능)
- **리스크 점수**: P × I × (1 - D) — 높을수록 위험

### 5.2 리스크 상위 5

#### Risk #1: Echo 시스템의 대규모 동시성 서버 부하

| 항목 | 값 |
|---|---|
| **점수** | 0.65 × 9 × 0.35 = **2.05** |
| **발생 확률** | 65% — 선례 없는 동시 다중 Echo 상호작용, O(n²) 가능성 보유 |
| **영향도** | 9 — 코어 판매 포인트(Echo)가 기술적 한계로 크게 제한되면 제품 정체성 붕괴 |
| **감지 난이도** | 중간 — 서버 부하는 소규모 플레이테스트로는 드러나지 않고 30+ Echo 동시 테스트 필요 |

**검증 실험:** Echo 동시성 부하 프로토타입 (Priority 1)
- 목표: 40 Echo + 10 생존자 환경에서 서버 CPU 70% 이하, 틱레이트 30Hz 유지
- 방법: UE5 Dedicated Server + 더미 클라이언트 50대로 자동화 부하 테스트
- 기간: 프리프로덕션 3-5개월 차
- 판정 기준: 30Hz 드롭 없이 40 Echo 안정 동작 → 통과. 실패 시 Echo 수 제한·빈도 제한 설계 변경

## 핵심 발견사항 및 권고

### 1. Echo 동시성 — 가장 시급한 검증 대상

Echo 시스템의 기술적 구현은 가능하다. 진짜 질문은 **"57명이 동시에 Echo일 때도 서버가 버티는가"** 이다. Echo 간 Dispel 상호작용, Soulflare 전역 브로드캐스트, Haunt 구역 충돌 검사가 모두 동시에 발생할 때의 서버 CPU·대역폭을 프리프로덕션 3-5개월 차에 반드시 검증해야 한다.

### 2. 제안서 불일치 사항

| 항목 | 문제 |
|---|---|
| **인원 수** | 검토 범위(이슈)는 "100인"을 언급하나 제안서 본문은 "60인"이다. 100인으로 확장할 경우 본 검토의 GREEN 항목 다수가 YELLOW 또는 RED로 변환된다. 크리에이티브 디렉터에게 60인으로 확정할지 확인 필요 |
| **AI 개체 수** | "20~40체"로 명시되어 있으나 이는 플레이어 수·시리즈 S 메모리 제약과 상충 가능성 있음 |
| **개발 기간** | "3.5년"과 실제 추정치 간에 30% 갭이 존재한다. 버퍼를 포함한 4.5년(55개월)이 현실적 |

### 3. 엔진 선택 — UE5 외 대안 검토

**제안서의 UE5 선택은 타당하다.** 다만 트레이드오프를 제시한다:

| 엔진 | 장점 | 단점 | ECLIPSE 적합도 |
|---|---|---|---|
| **Unreal Engine 5** | Lumen+Nanite(고딕 환경 최적), Niagara(VFX), Lyra(네트워크 참조), World Partition(대형 맵), PS5/Xbox 1차 지원 | C++ 진입 장벽, 대규모 팀 운영 복잡성, Series S에서 Lumen 제약 | **90%** — 제안된 모든 기술 요구사항을 커버. 가장 큰 리스크인 Series S는 어떤 엔진을 써도 동일하게 존재 |
| **Unity 6** | C# 생산성, 중소규모 팀에 적합, 크로스플랫폼 강점 | BR급 네트워킹 풀스택을 직접 구축 필요, Lumen/Nanite급 GI 없음, 고퀄리티 고딕 비주얼에 추가 커스텀 셰이더 필요 | **60%** — 네트워킹·렌더링 양측에서 대규모 커스텀 작업 필요 |
